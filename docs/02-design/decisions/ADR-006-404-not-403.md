# ADR-006 Out-of-scope records return 404, not 403
> Status: Accepted | Date: unknown

## Context
Distinguishing "exists but not yours" from "does not exist" leaks the registry to anyone probing ids.

## Decision
Any record the caller cannot access by scope is treated as nonexistent: repositories filter by a scope predicate built from `ICurrentUser`, and handlers throw `NotFoundException` → HTTP 404. HTTP 403 is reserved for policy failures (role vs endpoint). Code-uniqueness probes are unscoped on purpose (codes are unique system-wide, and a duplicate must fail regardless of viewer).

## Consequences
- Id enumeration cannot reveal other facilities' data.
- Debugging "missing" records must account for scope (the record may exist for someone else).
- UX copy must never say "you are not allowed to see this" on 404.

## Alternatives considered
- 403 with a generic message — rejected: still confirms existence.
